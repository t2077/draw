# 画线工具

给亚克力桥画刀路用。黑线是刀路中心线，红线是刀缝边（刀缝半径 1 mm，两侧各一条）。

## 打开

直接开：**https://t2077.github.io/draw/**

本地跑：**不要直接双击 `index.html`** —— ES module 和 localStorage 在 `file://` 下会被
浏览器挡住。起一个静态服务就行：

```
python -m http.server 8000
```

然后进 `http://localhost:8000/`。Caddy / nginx / `npx serve` 都一样。

> 存档存在浏览器的 localStorage 里，按**域名**分开。GitHub Pages 和你本地服务是两个
> 不同的源，各存各的，导出的 JSON 可以互相导入。

## 文件

```
index.html    页面：一排按钮 + 一块画布
style.css     样式
js/geom.js    几何：刀具半径偏移（平行线 + 顶点圆弧）、吸附、销孔、掏角矩形
js/store.js   localStorage 多存档
js/main.js    状态、事件、渲染
json2dxf.py   导出 JSON → DXF（红线裁进 195×95，Layer 0，R2000）
```

销孔尺寸 `SLOT_W × SLOT_L = 2.5 × 4.7`、掏角半径 `RELIEF = 0.07` 在 `js/geom.js` 顶部和
`json2dxf.py` 里各有一份，改的时候两边都要动。

## 画布

195 × 95 mm，左下角是原点，y 轴向上。小格 1 mm，大格 10 mm。

## 红线是怎么来的

红线是**半径 1 mm 的刀路**：到最近黑线距离恰好 1 mm 的那一圈，三部分拼成——

- 每段黑线两侧的平行偏移线
- **外角**：R = 1 mm 的圆弧（刀转弯，转不出尖角）
- **自由端**：半圆帽（刀是圆的）

所以红线**整圈闭合**，而且离黑线处处恰为 1 mm。这条用数值验过：把红线所有端点归并，**没有一个落单**（落单就是断口），端点到最近黑线的距离 1 ± 1.4e-14 mm——就是双精度的极限，没有肉眼能看见的误差。

红线是**派生**的，不进存档：改黑线或删黑线，整圈立刻重算。两条黑线靠得比 2 mm 还近时，中间那两条偏移线会被剪掉——因为那里的点离另一条黑线已经不足 1 mm，不属于刀路。

### 剪裁为什么必须算角度，不能采样

偏移线和圆弧都要被别的黑线剪掉。**剪裁量只有解析解才行**：

- 圆弧若按采样点逐个判「这点被吞掉没有」，被吞掉一个采样点，整条弧就在那里断成两截，断口正好是一个弦长。d = 1 mm、步长 7.5° 时是 0.13 mm，放大看得见。
- 现在按**角度区间**扣：圆心 V、半径 d 的圆上，落进某条黑线胶囊（距离 < d）的 φ 集合是解析的——
  两端各一个 d 圆盘给一个 `cos(φ−ψ) < −ρ/(2d)`；到无限直线的距离 < d 给一个 cos 带；垂足落在段内再给一个 cos 带，两者求交。
  区间的边界全落在相切点上，于是圆弧端口和偏移线端口严丝合缝。

三个坑都踩过：`{cos u < k}` 在 `k ≤ −1` 时无解、`k > 1` 时才是整圆（写反过一次，两条黑线正好相距 2d 时整条弧蒸发）；整圆写成 `[0,2π]` 换个相位就是 `[ν, ν+2π]`，跟另一个整圆求交前必须各自铺开 ±2π，否则会被裁成半圈；圆弧只跳过**端点落在该顶点上**的黑线，穿过该顶点的黑线（T 形接头）恰恰要把弧整条吞掉。

### 微调

选中东西以后：

- **方向键**：挪 0.1 mm；按住 `Shift` 挪 1 mm。框选的顶点、销孔组件、整个矩形都能挪。
- **`[` `]`**：把选中的**销孔组件或矩形**转 −1° / +1°；`Shift` 是 ±10°，`Alt` 是 ±0.1°。
- **拖转向把手**：矩形和销孔组件选中后，边上会多一个蓝色圆点（在矩形自己横轴的外侧），
  拖它就转。转角和销孔一样：吸附开着吸到 5°，关掉就随手。

连按一串只记一步撤销（相隔 700 ms 内算同一串），不会把撤销历史挤爆。

## 选中矩形后的输入框

选中**一个**矩形，工具栏下面会多出一条：`宽 / 高 / 中心X / 中心Y / 转角`，直接敲数字就行，
改完立刻生效（宽高按同一个中心对称地变）。

- 边打边改（`input` 事件），失焦或回车时才把这一整次编辑记成**一步**撤销。
- 面板是常驻 DOM，每帧只更新 `value` 和 `hidden`——每帧重建输入框的话，焦点会被打断，
  字打到一半就没了。正在输入的那个框不会被覆盖。
- 输入框里打字不会触发工具快捷键（`keydown` 先看 `event.target` 是不是输入框）。

## 矩形的转角

矩形存 `{ a, b, angle }`：`a`、`b` 是**未旋转**的一对对角，整体绕自己的中心转 `angle` 度
（逆时针，跟销孔一个方向）。缺省 0，就是轴对齐。

- 转过的矩形渲染成 `<polygon>`，轴对齐的还是 `<rect>`（保住 crispEdges）。
- 拖角点改尺寸在矩形自己的坐标系里算，所以**转过的矩形也永远是矩形**。
- 定框只用**动过的角 + 它们的对角**。四个角一起取包围盒是错的：另外三个角会按原位
  把框撑住，往里拖就等于没拖（转到别的角上就正常，所以现象是「时灵时不灵」）。
  对角要是也被拖过，它在局部坐标里已经是新位置，直接用就行 —— 所以拖满四个角是平移。
- 黑线的刀路（`rectangleEdges`）、吸附端点、框选、DXF 导出全部走 `rectangleCorner`，
  自动带上转角。

红线是黑线派生出来的，不存进存档：改黑线或删黑线，红线立刻跟着变。

## 框选顶点与成批微调

`选择` 模式下，从空处拖鼠标会拉出一个**框**，松手后框内顶点整批选中：

- 只有**黑线的两端**和**矩形的四角**能进框，销孔和红线不参与。
- 顶点画成橙色实心方块，跟整图元选中的白框区分。
- 抓到框里任一顶点拖动，整批一起走；方向键微调同理。`Ctrl` 拖动 = 在已有选择上追加。

**矩形顶点批量挪动时，矩形永远是矩形。** 做法是：先把每个角点的最终位置全算出来，
再取它们的包围盒当 `a`/`b`。于是拖一个角是改尺寸，拖两个角还是矩形，拖满四个就是平移，
不会变成平行四边形。

## 掏角矩形

四角是 90° 的矩形，在激光下角上会留个尖。掏角矩形把四个顶角换成 r = 0.07 mm 的
**180° 圆弧**。**销孔组件（连接头）里的每个长圆孔本来就是这种**，不用另外选对象；
`掏角矩形·红` 只是给别的地方手画用的。

- 圆心在角点沿对角线往内、每轴偏 `r/√2` —— 也就是离角点恰好 `r`；半径取 `r` 时，
  圆正好**过角点**。
- 圆上两个切点落在两条边上、离角点 `r·√2`，它们到圆心的距离也是 `r`，所以也恰在圆上；
  这两点关于圆心对径，于是那段弧正好是半圆。
- 四条边在切点处收住，由四段半圆接起来。

推导见 `js/geom.js` 的 `reliefRect`。导出 DXF 时是 4 条 LINE + 4 段 ARC。

## 上下对称

勾上 `对称`，轴上下一模一样。

**对称轴就是一个普通黑实体**，不是特例：它照吃刀（有红线）、能选能拖、一直在图上。
带上 `sym: true` 只表示「这条是镜面」。勾选框只决定镜不镜像，管不着它的存在——
取消勾选，线留在原地。

- 勾 `对称` 时**先找图上已有的**横贯画布的黑线段，把它标成轴（有多条就挑离画布中线
  最近的那条）；一条都没有才新画一条 y = 47.5 的。自己画的轴就是轴，工具不伪造第二条。
- 拖着轴上下挪，镜面跟着挪。
- **轴自己不镜像**（关于自己镜像还是自己），但它的刀路照算——它是切割轮廓。

对称的那一份**不进存档**，跟派生红线一样每次重算。做法不是另写一套镜像绘制，而是让
`displayEntities()` 多吐一份镜像，`blackSegments()` 从它取黑线——于是刀路（`roundedOffset`）
自己就把红线镜像过去了，销孔、手画红线也走同一条路。

- 镜像那份黑线画淡一点（opacity 0.45），一眼分得出哪份是抄的。
- 镜像是**反射**不是平移：销孔组件关于水平轴翻过去时，本地 y 一起翻向——
  下挂孔会跑到长排的另一侧，孔自身的转角也跟着反向（`geom.pinHoles` 的 `flipped`）。

导出的是 `{ slot, sym, entities }`：`entities` 全是原始图元，没有派生红线、没有镜像副本，
重新导入不会翻倍；`sym` 带回对称开关的状态。

`json2dxf.py` 用同一条规则再算一遍镜像，所以 DXF 拿到的是完整的一张图，不是半张。

## 操作

- 滚轮缩放（以鼠标为中心）
- 触摸屏双指缩放（捏合），单指画线
- Shift 拖动或中键拖动平移
- 选中图元后拖顶点改形状（先改后记，Ctrl+Z 退回原样）
- Ctrl+Z 撤销，Esc 取消选择
- 坐标跟着光标走，悬停和拖动时显示的都是吸附后的坐标

**页面本身不缩放**（`html, body { touch-action: none }` + viewport `user-scalable=no`）。
不这么写的话，同一个捏合手势浏览器要缩放整页、画布也要缩放自己，两边抢同一个手势，
表现就是"缩放乱跳"。另外 `pointerup` 在 `window` 上也挂了一份兜底：手指被系统手势
打断时事件会丢，留在表里的幽灵指针会让缩放一直跟着剩下那根手指走，停不下来。

## 吸附

三条规则，按优先级：

- **端点**：离任何端点 6 屏幕像素内 → 吸过去，终点画橙圈
- **网格**：离格线半格以内 → 归到最近的格线，x、y 各自判断。于是落点一定是整毫米
- **正交**：相对起点既要在 4° 以内、垂直偏移又不超过 6 像素，才拉平或拉直。
  光看角度不行：100 mm 外偏 4° 就是 7 mm，鼠标会被硬拽走一大截，所以加了距离闸

`吸附` `网格` 是两个独立开关（`6` 键开关吸附），**按住 Alt 临时关掉吸附**。关掉 `网格` 连格线也不画。

**吸附关掉就是真的自由**：销孔落点不再归整毫米，转角也不再被吸到 5° 的倍数——
鼠标给多少是多少，再用方向键 / 方括号微调。开着吸附时才是整毫米落点 + 5° 转角。

**悬停时就按同一套规则吸**，所以起笔之前就能看见这一下会落在哪。吸到端点画橙圈；吸到网格不画圈——格线本身就是参照，再套个圈纯属添乱。

阈值在 `js/main.js` 顶部：`SNAP_PIXELS` / `ORTHO_DEGREES`。

端点在图上画成小黑点，半径固定 2.5 屏幕像素，缩放时不变大。

## 边界

黑线一律压在 195 × 95 的画布内，拖到外面会自动压回边界（红线是刀路，允许压出画布）。
